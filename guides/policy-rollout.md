# 개정안 시행 준비

현재 v1.1은 미시행 개정안입니다. PR 병합, 문서 게시, 멤버 승인과 개별 계약 동의는 서로 다른 단계입니다.

## 1. 검토본 확정

PR의 최종 커밋을 기록하고 내용·링크·검사 결과를 확인합니다. 실제 계약 당사자와 권리 관계에 맞는 전문가 검토가 필요한 부분을 정리합니다. 공통 문서만으로 확인할 수 없는 사실을 확정했다고 표시하지 않습니다.

## 2. 운영 정보 준비

| 항목 | 담당자가 확정할 내용 |
| :--- | :--- |
| 일반 분쟁·계약 연락 | 실제 사용할 비공개 채널과 접근 담당자 |
| 프로젝트 책임 | 오너·지급 책임자·검수 담당자 |
| 권리 증빙 | 문서 보관 위치, 접근자, 삭제·재검토 기준 |
| 대체 담당 | 오너 부재 시 연락·조정 담당 |
| 정책 적용 | 기존 참여자의 적용 버전과 미지급액 |

이 정보를 마련하지 않은 상태에서 개인정보·계약 원본을 받거나 새 약정 참여를 확정하지 않습니다. 공개 핸드북에는 필요한 안내만 표시합니다.

## 3. 공지와 승인

[공지 초안](../templates/POLICY_NOTICE.md)의 빈칸을 채워 기존 운영 규칙에 맞는 공간에 게시합니다. 게시 링크와 시각을 기록하고 최소 7일을 확보합니다. 투표 대상 멤버 수와 명시적 승인 결과를 남깁니다. 초안 파일 저장이나 PR 생성만으로 공지가 시작된 것으로 보지 않습니다.

## 4. 시행

요건을 충족한 뒤 시행일·적용 범위를 확정하고, 문서의 개정안 표시를 시행 정보로 바꿉니다. CHANGELOG에 공지·승인·최종 커밋을 기록합니다. 새 프로젝트 양식의 버전과 문서 링크도 일치시킵니다.

기여자 검사기와 재사용 워크플로는 검토한 커밋에 고정합니다. 기존 프로젝트는 갱신 PR에서 현재 장부가 새 검사를 통과하는지 확인합니다. 이력 오류가 있으면 과거를 덮어쓰지 말고 정정 근거를 남깁니다. 도구 갱신으로 계약 버전이 바뀌지는 않습니다.

## 5. 기존 프로젝트 전환

현재 적용 약정·특약, 기여자 비율, 이용허락 기간, 보류·미지급액을 먼저 정리합니다. 동의받지 않은 기존 약정을 새 버전으로 덮어쓰지 않습니다. 새 버전 적용을 합의한 사람은 [동의 확인](../templates/ACKNOWLEDGEMENT.md)을 남깁니다.

## 6. 시행 후 점검

첫 등록·정산·탈퇴 처리 때 절차가 실제로 작동하는지 확인하고 누락된 양식·연락 경로를 수정합니다. 시행일과 소급 금지, 원본 기록을 유지하며 수정 이유를 남깁니다. 다음 점검일과 담당자는 결정 기록으로 지정합니다.
