## 라벨은 작은 안내판

**유형 1개 + 분야 0~2개 + 필요한 상태 1개** 정도면 충분합니다. 분야를 드롭다운에서 골랐다고 라벨이 자동으로 붙지는 않습니다. 유형 라벨은 양식에서 붙고, 분야·상태는 권한이 있는 사람이 정리합니다.

- `bug` + `분야: 스크립트` + `상태: 확인 필요`: 문이 두 번 열리는 오류를 재현해 주세요.
- `작업` + `분야: 맵·조명` + `good first issue`: 대기실 안내 표지 세 개를 배치해요.
- `플레이테스트` + `분야: QA`: 모바일에서 튜토리얼을 확인해요.
- `상태: 도움 필요`: 본문에 막힌 이유와 필요한 도움을 함께 적어요.

진행 상태는 바뀔 때 이전 상태 라벨을 제거합니다. 끝난 작업은 이슈를 닫으면 되므로 완료 라벨은 따로 만들지 않습니다. `good first issue`는 설명·완료 기준·확인 방법이 준비된 작은 작업에 붙입니다. 모든 새 작업에 자동으로 붙이지 않습니다.

전체 라벨의 이름·색·설명은 [라벨 도감](labels.md)과 [설정 원본](../.github/labels.yml)에서 관리합니다. 기존 영문 기본 라벨 이름은 검색·도구 호환을 위해 유지하고 설명을 한국어로 제공합니다.

## 작은 작업 하나를 끝내는 흐름

1. 이슈에 목표·범위·완료 기준을 적습니다. 같은 작업이 이미 있는지 검색합니다.
2. 담당자와 범위를 맞추고 브랜치를 만듭니다. 예: `feat/42-door-interaction`, `fix/58-mobile-button`, `docs/studio-setup`.
3. 한 커밋에는 설명 가능한 변화 하나를 담습니다. 예: `feat: 문 상호작용 추가`, `fix: 모바일 버튼 겹침 수정`.
4. 아직 만드는 중이면 Draft PR로 먼저 공유합니다. 리뷰가 필요해지면 Ready for review로 전환합니다.
5. PR에 실제 확인한 환경과 결과를 적습니다. UI·맵 변경은 전/후 화면, 게임 시스템은 가능하면 서버·클라이언트와 2인 테스트 결과를 남깁니다.
6. 리뷰를 반영하고 해당 저장소의 절차에 따라 merge합니다. 해결된 이슈를 닫고 필요 없어진 작업 브랜치를 정리합니다.

이름 예시는 권장 방식이며 기존 프로젝트 규칙이 있으면 그 규칙을 따릅니다. 정식 기여자 등록과 보상은 [참여 가이드](../CONTRIBUTING.md)의 별도 절차입니다.

```sh
git switch main
git pull --ff-only
git switch -c feat/42-door-interaction
# 작업 후 필요한 파일만 선택해서 추가합니다.
git add path/to/changed-file
git commit -m "feat: 문 상호작용 추가"
git push -u origin feat/42-door-interaction
```

## Roblox 공동 작업에서 특히 유용한 습관

- `.rbxl` 같은 바이너리 파일은 텍스트처럼 합치기 어렵습니다. 같은 place 파일을 동시에 수정하기 전에 담당 범위를 맞추세요.
- Team Create와 Git/Rojo 중 무엇을 기준으로 동기화하는지는 프로젝트 README에 적습니다. 확인 없이 양쪽에서 덮어쓰지 않습니다.
- 맵·모델·사운드는 파일만 보고 변경을 판단하기 어렵습니다. 이미지·짧은 영상·테스트 장소를 PR에 함께 남깁니다.
- 충돌을 해결할 때는 어느 쪽이 최신인지 추측하지 말고 작성자와 비교합니다. 해결 후 Studio에서 다시 열어 확인합니다.

## 리뷰는 사람 대신 작업을 봐요

`질문:` 의도를 알고 싶어요. / `제안:` 이런 대안도 있어요. / `필수:` merge 전에 해결할 문제와 이유가 있어요.

“이거 이상해요” 대신 “모바일에서 버튼이 가려져요. 오른쪽 여백을 늘리면 어떨까요?”처럼 상황과 이유를 붙입니다. 좋은 선택이나 배운 점도 남겨 주세요.

## 가볍게 즐기는 커뮤니티

아래는 자유롭게 써볼 주제입니다. 자동 게시나 의무 일정은 없습니다.

- **오늘의 10초**: 작품 자랑에 짧은 작업 영상 하나.
- **이번 주 작은 승리**: 드디어 고친 버그, 처음 만든 애니메이션, 끝낸 문서 한 장.
- **버그 탐정**: Q&A에서 재현 방법을 좁히고 해결 과정을 함께 기록.
- **다음 플레이는?**: [투표 예시](../templates/discussions/투표.md)로 다음 테스트 주제 모으기.

릴리스 때는 [업데이트 노트](../templates/RELEASE_NOTES.md)를 복사해 플레이어가 체감하는 변화와 알려진 문제를 알려 주세요.

## 저장소 운영자용

- 조직 기본 이슈·PR 양식은 자체 양식이 없는 저장소에 상속됩니다. 자체 `ISSUE_TEMPLATE` 폴더가 있으면 조직 기본 이슈 양식이 합쳐지지 않습니다.
- `.github`의 워크플로는 다른 저장소로 자동 복사되지 않습니다. 기존 기여자 검사 워크플로는 기존 설치 안내를 따릅니다.
- 라벨도 자동 상속되지 않습니다. 새 저장소에는 아래 명령으로 미리보기 후 적용합니다. 기존 라벨을 삭제하거나 이름을 바꾸지 않습니다.

```sh
python3 -m pip install pyyaml==6.0.2
python3 scripts/sync_labels.py --repo sickBoyStudio/새저장소
python3 scripts/sync_labels.py --repo sickBoyStudio/새저장소 --apply
```

명령은 이 `.github` 저장소를 내려받은 폴더에서 실행하고 GitHub CLI 로그인이 필요합니다. `소통:` 라벨은 커뮤니티 저장소에만 적용합니다. 양식을 수정하면 자동 검사에서 필드 구조와 참조 라벨을 확인합니다.
