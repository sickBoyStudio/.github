# 프로젝트 소개 작성 안내

다른 개발자가 프로젝트를 보고 자신이 맡을 일을 떠올릴 수 있도록 소개합니다. **각 프로젝트 담당자는 저장소의 짧은 설명(About), 태그(Topics), README를 직접 작성하고 진행 상황이 바뀌면 갱신해 주세요.**

[README 양식](../templates/README.md)을 복사해 실제 프로젝트 내용으로 채웁니다. 소개는 다음 순서면 충분합니다.

1. 어떤 게임·도구인지 한두 문장.
2. 실제 화면 또는 짧은 시연과 플레이 방식.
3. 스토리가 있다면 배경·사건·플레이어 목표.
4. 구현된 것과 아직 남은 일.
5. 다른 개발자가 처음 맡아볼 작업, 완료 기준과 연락 경로.

## 저장소의 짧은 설명

About의 Description에는 **플랫폼 + 장르·유형 + 핵심 경험**을 한 문장으로 적습니다. ‘대작 개발 중’, ‘개발자 모집’만으로 끝내지 않습니다. 공개 출시·플레이 인원·모집 여부는 확인된 사실만 씁니다.

예시 형식: `Roblox 협동 퍼즐 게임 — 장치를 함께 조작해 폐쇄된 공간의 출구를 찾는 프로젝트.`

## 태그를 직접 붙여 주세요

저장소 About 옆 설정에서 Topics를 입력합니다. 플랫폼·유형은 기본으로, 장르와 플레이 방식은 해당하는 것만 선택합니다.

| 분류 | 사용할 수 있는 태그 예시 |
| :--- | :--- |
| 플랫폼 | `roblox` |
| 프로젝트 유형 | `roblox-game`, `npc-ai`, `level-design`, `roblox-plugin`, `developer-tools` |
| 장르 | `horror`, `psychological-horror`, `survival`, `puzzle`, `adventure`, `roleplay`, `simulation`, `obby`, `social` |
| 플레이 방식 | `singleplayer`, `multiplayer`, `co-op`, `pvp`, `pve`, `escape-game` |
| 기술 | `luau`, `rojo`, `blender` |

예를 들어 Roblox 공포 게임이라면 `roblox`, `roblox-game`, `horror`를 먼저 붙이고 실제 플레이 방식에 맞는 태그를 추가합니다. 전부 붙이지 말고 보통 4~8개로 설명합니다. 개발 단계·담당자·모집 상태는 README에 적습니다.

GitHub Topics는 소문자·숫자·하이픈을 사용하며 최대 20개, 태그당 50자 이내입니다. 태그 이름에는 비밀정보를 넣지 않습니다. [GitHub 공식 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics)

## 참여할 일을 구체적으로

‘프로그래머 구함’ 대신 `추격 중 막히는 구간을 재현하고 위치·조건을 기록하기`처럼 시작점과 결과물을 적습니다. 확정 모집이 아니라면 ‘참여 제안 가능 작업’으로 표시합니다. 개발자뿐 아니라 맵·사운드·UI·테스트·문서 역할도 실제 필요한 만큼 소개합니다.

작업 시작 전에는 담당자와 범위·검수·보상·권리를 확인합니다. 소개 페이지가 기존 약정을 대체하거나 보상을 자동 확정하지 않습니다.

## 스토리와 공개 범위

스토리가 있으면 README에 짧은 도입을 씁니다. 상세 설정·결말·반전은 별도 문서에 두고 스포일러라고 표시합니다. 기획 목표와 실제 구현을 구분하며 없는 설정을 홍보용으로 덧붙이지 않습니다.

비공개 프로젝트는 내부 README를 충분히 작성하되, 스튜디오 첫 화면에는 담당자가 공개를 허락한 이름·설명·태그만 소개합니다. 접근할 수 없는 저장소 링크 대신 공개된 문의 경로를 제공합니다. 이미지·시연·설정 공개도 각각 확인합니다.
