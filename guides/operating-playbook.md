# 참여부터 종료까지 운영 절차

> v1.1 개정안과 함께 검토할 운영안입니다. 새 의무는 승인·시행 전 기존 참여자에게 적용하지 않습니다.

## 단계별 담당과 완료 기록

| 단계 | 담당 | 완료하기 전에 확인할 것 | 남길 기록 |
| :--- | :--- | :--- | :--- |
| 문의·참여 제안 | 프로젝트 담당자 | 하고 싶은 일, 가능한 범위, 공개 가능한 자료 | 모집 글·작업 이슈 |
| 착수 승인 | 오너와 참여자 | 작업 범위·완료 기준·보상·권리·적용 버전 | 양측이 확인한 작업 합의 |
| 접근 부여 | 권한 관리자 | 담당 업무에 필요한 저장소·서비스 권한 | 부여 대상·범위·기간·승인 기록 |
| 제출·검수 | 제출자와 검토자 | 소스·에셋·출처·실행 방법·검수 기준 충족 | 작업 PR·검수 기록 |
| 기여자 등록 | 본인과 오너 | 실제 작업, 약정 동의, 비율·상한·적용일 | 장부 변경 PR와 동의 확인 |
| 출시 | 출시 승인자 | 권리 명세·보안·테스트·지급 설정·복구 방법 | 릴리스와 출시 확인표 |
| 월별 정산 | 오너와 확인 담당 | 거래 원장·비율·차액·보류·실제 지급 | 제한된 접근 공간의 정산서 |
| 변경·분쟁 | 이해관계 없는 담당 | 적용 버전·증거·통지·답변·미지급액 | 결정 또는 분쟁 기록 |
| 탈퇴·종료·이전 | 이전·신규 담당과 당사자 | 남은 작업·권한·권리·잔액·보관 책임 | 인수인계와 종료 확인 |

역할이 겹칠 수 있지만 자기 사건의 분쟁 판단은 다른 담당자에게 맡깁니다. 기술적 검사 통과와 당사자 동의를 구분합니다. 별도 합의가 없으면 지급 시작일·비율·권리 범위를 추정해서 진행하지 않습니다.

## 작업을 시작하지 않는 경우

- 권리자나 사용 조건이 확인되지 않은 코드·에셋이 있다.
- 보상을 전제로 작업하는데 비율·등록 조건·적용일이 합의되지 않았다.
- 법정대리인 등 필요한 동의 확인 경로가 마련되지 않았다.
- 공개 여부·제출 공간이 불명확해 개인정보나 비밀자료가 노출될 수 있다.

담당자는 미확정 항목과 해결 담당자를 적고 다음 확인 일정을 안내합니다. 참여자에게 무응답 상태로 추가 작업을 계속 요구하지 않습니다.

## 정기 운영 일정

- 매월 10일까지: 전월 정산서·지급 또는 지급 제한과 다음 확인일 안내. 세부 기준은 수익 배분 규칙을 따릅니다.
- 분기마다: 역할·접근 권한·연락 경로·문서 링크·보관 자료 필요성 점검.
- 매 릴리스: 자산 권리 명세, 실제 배포 버전, 백업·복구 확인.
- 담당자 변경 시: 저장소뿐 아니라 Roblox·외부 서비스 권한도 함께 검토.

## 자주 생기는 상황

| 상황 | 처리 |
| :--- | :--- |
| PR은 병합됐는데 등록이 늦어짐 | 사전 합의와 검수 기록을 연결해 오너가 누락 여부 확인. 무조건 새 작업을 요구하지 않음 |
| 자동 분배 금액이 장부와 다름 | 실제 거래·적용일·중복 분배·과거 구독 비율을 대조하고 차액 기록 |
| 기존 코드를 수정해 원본과 모양이 달라짐 | 자산 이력과 실제 사용 관계 확인. 파일명이나 줄 수만으로 권리·기여를 없애지 않음 |
| 담당자가 연락되지 않음 | 대체 연락과 운영진 조정 경로 사용. 계정 탈취나 임의 소유권 이전으로 해결하지 않음 |
| 공개 이슈에 비밀정보가 올라옴 | 추가 복제를 줄이고 보안 담당자에게 알림. 키라면 먼저 폐기·교체. 증거는 제한된 공간에 보존 |
| 새 정책에 동의하지 않음 | 기존 적용 버전을 확인하고 변경 협의. 단순 무응답을 동의로 처리하지 않음 |
