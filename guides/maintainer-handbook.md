# 관리자 안내

## 담당자

현재 조직 운영진은 권한이 있는 관리자가 GitHub 조직의 Owner 역할로 확인합니다. 비공개 멤버 목록을 공개 문서에 옮기지 않습니다. 공개할 담당자와 연락 경로는 본인 확인 후 게시하며, 특정 계정을 모든 프로젝트의 계약 대표자로 간주하지 않습니다.

프로젝트 README에 오너, 리뷰 담당자, 보안 접수 경로와 지원 범위를 적습니다. CODEOWNERS는 실제 리뷰 책임자가 동의한 뒤 해당 저장소에 설정합니다. 조직 전체에 한 사람을 일괄 지정하지 않습니다.

## 이슈와 PR

중복·재현 여부·영향 범위를 먼저 확인합니다. 작업 담당자와 수용 기준을 정하고 변경 내용을 검토합니다. 문서 수정에 Studio 실행을 요구하지 않는 등 실제 변경에 맞는 검증을 선택합니다. 보상 합의가 필요한 작업은 구현 전에 정리합니다.

외부 기여의 코드를 실행할 때 비밀정보와 쓰기 권한을 넘기지 않습니다. 워크플로 권한은 최소화하고, 외부 액션과 공통 검사기는 검토한 버전으로 고정합니다.

## 출시와 장애

출시 승인자, 버전, 테스트와 되돌리는 방법을 기록합니다. 장애 발생 시 담당자·영향 범위·임시 조치와 다음 안내 시간을 정하고, 해결 후 원인과 재발 방지를 기록합니다. 원인 미확인 상태에서 특정 기여자 책임을 발표하지 않습니다.

## 정기 점검

매월 정산·미지급액을 확인하고, 분기마다 권한·연락 경로·지원 범위·외부 라이선스를 점검합니다. 퇴사·탈퇴·역할 변경 시 키·계정 권한과 외부 서비스 권한을 함께 확인합니다.
