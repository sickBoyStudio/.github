# 코드·에셋의 권리와 관리

> v1.1 개정안 · 미시행. 공지·승인과 시행일 확정 후 적용합니다. 기존 약정에 소급하지 않으며, 새 약정은 당사자가 최종 문서와 적용 범위를 확인하고 동의해야 합니다.

## 1. 목적과 적용

코드, 모델, 맵, UI, 이미지, 폰트, 음악, 애니메이션, 기획 문서, 빌드·배포 자료를 프로젝트 자산으로 관리합니다. 자산으로 관리한다는 말은 모든 자료가 저작권으로 보호된다거나 조직이 모두 소유한다는 뜻이 아닙니다. 보호 대상·권리자·이용 조건은 자료별로 확인합니다.

이 문서는 [기여자 약정](contributor-agreement.md)의 세부 기준입니다. 이를 적용하는 작업 합의에는 문서의 고정 커밋 링크를 명시합니다. 미작성·미확인 항목을 무제한 이용이나 포괄 양도에 대한 동의로 해석하지 않습니다.

## 2. 자산 종류와 권리 근거

| 구분 | 확인할 내용 | 적용 원칙 |
| :--- | :--- | :--- |
| 참여 전에 보유한 코드·도구 | 원본 버전, 권리자, 기존 계약과 사용 범위 | 프로젝트 제출만으로 소유권을 넘긴 것으로 보지 않음 |
| 프로젝트에서 새로 만든 기여물 | 제작자, 작업 합의, 파일·PR·버전 | 별도 유효한 양도나 법적 귀속 근거가 없으면 권리자의 이용허락으로 사용 |
| 여러 사람이 수정한 결과물 | 원본과 각 수정 부분, 권리자별 허락 | 커밋 수나 작성 줄 수만으로 공동저작 여부·권리 비율을 확정하지 않음 |
| 외부 라이브러리·구매 에셋 | 원권리자, 버전, 라이선스·구매 조건 | 조직 규칙이나 비용 지급으로 원래 조건을 덮어쓰지 않음 |
| 생성형 도구 사용물 | 도구·사용 시점·입력 자료 권한·수정·검토 기록 | 독점권이나 무침해를 자동 보장하지 않음 |
| 계정·데이터·비밀정보 | 관리 주체, 접근 권한, 이용 목적 | 저작권 문서만으로 계정 양도·개인정보 이전을 허용하지 않음 |

외주비·급여·수익 배분 지급 사실만으로 모든 저작권을 취득했다고 단정하지 않습니다. 고용·업무상 창작 등 별도 귀속 근거가 있는 경우 실제 관계와 계약을 확인합니다.

## 3. 착수 전 필수 합의

[작업 사전 합의](../templates/WORK_AGREEMENT.md)와 [권리 명세](../templates/ASSET_REGISTER.md)에 아래 내용을 정합니다.

1. 계약 당사자와 권한, 적용 정책 버전, 연락 경로.
2. 대상 프로젝트·저장소·게임 ID와 결과물의 범위.
3. 기존 보유물·제3자 자료·신규 창작 부분의 구분.
4. 이용허락인지 양도인지, 지역·기간·플랫폼·수정·배포 범위.
5. 소스·편집 원본·빌드 설정·문서 등 납품 항목과 제외 항목.
6. 검수 기준·일정, 보상·비율·적용일, 중단 시 처리.
7. 크레딧·포트폴리오 공개, 탈퇴·해지 후 사용과 자료 보관.

권리 유형·대상·기간·보상 조건이 비어 있으면 해당 작업을 착수·배포 승인하지 않습니다. 기술적 검토가 필요하면 평가용 열람·실행 범위를 먼저 합의합니다. 기존 v1.0 작업의 권리를 새 기준으로 추정하지 않습니다.

## 4. 프로젝트 이용허락의 범위

새 약정에서 별도 양도를 선택하지 않는 경우 기본 방식은 **비독점적 프로젝트 이용허락**입니다. 다음 조건을 당사자가 명시적으로 채택하고, 대상 자산과 이용 기간을 특정해야 합니다.

- 명시된 게임의 개발, 테스트, 서비스 운영, 유지보수, 업데이트와 그 게임의 소개에 필요한 범위로 사용합니다.
- Roblox 서비스가 여러 지역에서 제공되는 경우 서비스 지역을 그에 맞게 명시합니다. 다른 플랫폼 이식, 후속작, 별도 게임, 독립 모듈 판매와 소스 공개는 별도 승인 대상입니다.
- 버그 수정, 호환성·보안 개선과 기능 변경에 필요한 편집 범위를 적습니다. 크레딧 삭제, 원작자 명예에 영향을 줄 수 있는 변경 등은 통상 편집에 모두 포함된 것으로 보지 않습니다.
- 실제 운영을 맡은 승인된 협업자·유지보수 담당자에게 필요한 범위만 접근시킵니다. 이들이 다른 프로젝트에서 재사용할 권한을 얻는 것은 아닙니다.
- 플랫폼 업로드나 서비스 제공에 필요한 권한은 명시한 배포 경로의 조건과 양립하는지 확인합니다. 플랫폼의 요구 권한을 줄 수 없으면 업로드하지 않습니다.
- 권리자의 일반적인 기술·경험과 별도 재사용 가능한 기존 도구의 이용을 일괄 금지하지 않습니다. 다른 사람의 기여물, 비밀정보와 프로젝트 전용 자료의 반출은 별도로 제한합니다.

허락이 실제로 종료되지 않은 한 단순 탈퇴·비활동·역할 변경만으로 이미 허락한 기간과 범위가 바뀌지 않습니다. 반대로 탈퇴를 이유로 합의한 지급·크레딧 의무를 없애지 않습니다. 기간 만료·해지 시 처리는 9장을 따릅니다.

## 5. 양도·독점·매각

저작재산권 양도나 독점적 이용은 별도 명시 합의로 합니다. 대상 파일·버전, 권리 종류, 2차적저작물 작성·수정 범위, 대가, 이전 시점, 기존 이용허락과 제3자 제한을 기재합니다. 비독점적 기본 약정에 ‘전부 귀속’ 한 줄을 추가하는 방식으로 처리하지 않습니다.

기여자가 넘길 수 없는 권리와 제3자 라이선스는 양도 대상에서 제외하고 목록을 남깁니다. 저작인격권을 포괄 양도·포기하는 조항으로 대체하지 않습니다. 프로그램과 다른 저작물의 법적 추정이 같다고 가정하지 않고 권리 범위를 명시합니다.

게임·IP 매각은 권리자 동의, 양수인, 이전 대상, 기존 수익 배분·미지급 의무와 대금 배분을 먼저 정합니다. 조직 승인이나 GitHub 저장소 이전만으로 권리자 동의를 대신하지 않습니다. 매각 수익은 [수익 배분 규칙](revenue-share.md#8-매각이전종료)을 따릅니다.

## 6. 제출·검수·등록

- 제출자는 파일·커밋·에셋 ID, 실행 방법, 알려진 문제, 외부 자료와 출처를 함께 제출합니다. 바이너리 자산은 편집 원본 제공 여부도 표시합니다.
- 오너는 제출 후 **7영업일 안에** 수락 또는 기준별 보완 사항과 다음 검토 일정을 안내합니다. 별도 합의가 없으면 영업일은 대한민국의 토·일요일과 공휴일을 제외하고 기한은 한국 시간으로 계산합니다.
- 무응답은 자동 검수 통과·권리 양도·보상 포기를 뜻하지 않습니다. 검토 지연을 이유로 추가 작업을 무기한 요구하지 않습니다.
- 최초 범위를 벗어나는 기능 추가는 보완 요구와 구분하고 보상·일정을 다시 합의합니다. 구체적인 검수 기준을 뒤늦게 바꾸지 않습니다.
- 검수 수락 기록, 작업 PR, 기여자 등록과 적용일을 연결합니다. 사전 합의된 보상 대상 기여물을 출시하면서 등록만 미루지 않습니다.
- 거절·취소된 결과물은 평가용으로 허락된 범위 밖에 사용하지 않습니다. 일부를 쓰려면 해당 범위와 보상을 다시 합의합니다.

## 7. 외부 자료와 생성형 도구

외부 자료 도입 시 상업 이용, 수정, 배포, 소스 공개 의무, 저작권 고지, 재허락과 플랫폼 업로드 조건을 확인합니다. 조건이 충돌하거나 원권리자를 확인할 수 없으면 해결 전 배포하지 않습니다. 출처·라이선스 사본이나 확인일과 근거 위치를 기록합니다.

비공개 코드·개인정보·계약 자료를 외부 AI 서비스에 입력하려면 승인된 도구와 데이터 처리 범위를 확인합니다. 도구 사용자의 계정 약관만으로 다른 권리자의 자료 전송이 허용되지는 않습니다. 생성 결과는 라이선스 충돌, 유사 코드·에셋, 보안 문제와 실행 동작을 검토하고 검토자를 남깁니다. 공개 크레딧에 비밀 프롬프트나 개인정보를 넣지 않습니다.

## 8. 보관·접근·백업

원본은 승인된 저장소·자산 저장 공간에 보관하고 개인 계정 하나에만 남겨 두지 않습니다. 계정 공유 대신 역할별 권한을 부여합니다. 외부 반출·공개·이전은 대상, 목적, 수신자, 허용 범위와 승인자를 기록합니다.

릴리스마다 소스 커밋, 바이너리·에셋 버전, 빌드 방법, 권리 명세와 크레딧을 연결하고 복구 가능한 백업을 확인합니다. 해시와 커밋은 버전 확인에 도움이 되지만 단독으로 저작권·계약 유효성을 입증한다고 보지 않습니다.

비공개 자료를 보호하려면 실제 접근 제한, 공유 승인, 비밀 표시와 반출 기록을 운영합니다. 문서에 ‘영업비밀’이라고 적었다는 이유만으로 법적 보호 요건이 모두 충족됐다고 설명하지 않습니다.

## 9. 탈퇴·해지·종료

탈퇴·제명 시 담당자는 권한 회수, 자산 목록, 인수인계, 사용 중인 버전과 미지급액을 확인합니다. 당사자가 합의한 기존 사용 기간과 보상은 별도로 관리합니다. 자기 계정을 삭제하거나 저장소 접근이 사라져도 합의 기록의 사본을 적법한 범위에서 확보할 수 있게 합니다.

계약 위반을 이유로 해지를 요구할 때는 위반 조항, 사실·증빙, 요구 조치와 기한을 합의된 비공개 경로로 통지합니다. 별도 합의가 없으면 **도달 확인 후 14일**의 시정 기간을 두고, 기한 만료 후 시정 여부와 해지 근거·효력일을 다시 명시합니다. 모든 위반이 자동 해지 사유가 되는 것은 아닙니다.

긴급한 유출·침해 또는 적용 법상 즉시 조치가 필요한 경우에는 필요한 범위의 임시 차단을 먼저 하고 이유와 재검토 일정을 남깁니다. 통상적인 시정 기간이 법적 권리 구제나 긴급 조치를 막지는 않습니다.

사용허락이 유효하게 끝난 자료는 신규 이용을 중단하고, 합의 또는 적법한 근거에 따라 배포 중단·교체·삭제 범위를 정합니다. 무조건 영구 사용하거나 즉시 모든 서비스를 파괴하는 것으로 처리하지 않습니다. 백업·분쟁 증거용 제한 보관은 신규 배포 권한과 구분합니다. 서비스 연속성이 필요하면 유지보수 전환 기간과 허용 범위를 사전에 합의합니다.

어느 쪽도 분쟁 해결을 위해 코드를 몰래 삭제·변조하거나 백도어, 킬스위치, 계정 탈취, 사용자 데이터 삭제로 압박하지 않습니다. 다툼이 없는 지급 의무와 기록 보존을 계속 이행합니다.

## 10. 증거·분쟁·책임

[분쟁 기록](../templates/DISPUTE_RECORD.md)에 쟁점, 적용 버전, 원본 증거, 변경 이력, 통지와 답변을 시간순으로 정리합니다. 원본을 보존하고 검토용 사본은 개인정보를 가립니다. 분쟁 자료를 공개 게시하거나 일괄 삭제하지 않습니다. 분쟁 보관 사유가 끝나면 [개인정보 기준](privacy.md)에 따라 필요성을 다시 검토합니다.

위반 주장만으로 무제한 배상, 모든 지분 박탈, 저작권 몰수나 형사책임을 확정하지 않습니다. 손해 발생, 원인과 귀책, 피해 방지 조치, 약정과 적용 법을 확인합니다. 합의금·손해배상과 정산금의 상계는 별도 유효한 근거를 확인합니다.

내부 협의·조정은 [운영 규칙](../GOVERNANCE.md#8-분쟁과-이의제기)에 따라 진행합니다. 소송·신고·가처분 등 적법한 외부 절차를 포기하도록 요구하지 않습니다. 정당한 신고와 법률상담을 비밀유지 위반으로 취급하지 않습니다.

소송이 발생하지 않는다는 보장은 아닙니다. 실제 체결 전에 계약 당사자, 미성년자 여부, 기존 권리와 양도·독점·해지 조건을 국내 변호사 등 적절한 전문가에게 검토받습니다. 전문가 검토 전 초안을 이미 법률 검토가 끝난 계약으로 표시하지 않습니다.
