# 저작권과 사용 허가

> v1.1 개정안 · 미시행. 공지·승인과 시행일 확정 후 적용합니다. 기존 합의는 당사자의 별도 동의 없이 변경하지 않습니다.

## 권리 확인

저장소 공개나 조직 가입만으로 코드·에셋의 자유로운 재사용이 허용되지는 않습니다. 해당 파일의 라이선스, 원권리자의 허락과 적용 법의 예외를 확인합니다. GitHub 약관에 따른 열람·포크와 프로젝트 밖 이용허락은 구분합니다.

오너가 저장소를 관리해도 모든 파일의 저작권자라는 뜻은 아닙니다. 외부 자료는 원래 라이선스를 유지합니다. 이 핸드북도 별도 라이선스 없이 조직 멤버 모두의 공동저작물로 단정하지 않습니다.

## 자산별 세부 기준

코드·에셋의 기존 소유권, 이용허락·양도, 검수·납품, 외부 도구 입력, 탈퇴 후 사용과 종료 처리는 [코드·에셋의 권리와 관리](code-and-asset-management.md)를 따릅니다. 자산별 [권리 명세](../templates/ASSET_REGISTER.md)를 작성하고 배포 버전과 연결합니다.

## 프로젝트에 넣을 때

`CREDITS.md`에 원본 URL, 버전·커밋·에셋 ID, 권리자, 라이선스와 허가 증빙을 남깁니다. 구매 내역이나 ‘무료’ 표기만으로 재배포·상업 이용이 가능한지 판단하지 않습니다. 폰트, 음악, 이미지, 플러그인과 생성형 도구 사용물도 확인합니다.

## 별도 허가 요청

기존 라이선스로 이미 허용된 사용은 그 조건을 따릅니다. 별도 허가가 필요한 경우 대상 파일과 버전, 사용할 프로젝트, 수정·상업 이용 범위, 기간, 대가와 크레딧을 적어 요청합니다.

오너와 관련 권리자가 실제 허가 권한을 확인하고 명시적으로 승인해야 합니다. 이모지, 무응답과 단순 이슈 종료는 허가가 아닙니다. 답이 없으면 사용을 시작하지 않습니다. 비공개 파일을 공개 요청에 첨부하지 않습니다.

## 공개와 이전

저장소를 오픈소스로 공개하거나 다른 조직으로 이전하기 전에 각 권리자의 허락, 외부 라이선스의 호환성, 비밀정보와 개인정보를 확인합니다. `templates/LICENSE`는 독점 프로젝트용 예시이며 모든 저장소에 자동 적용되는 조직 라이선스가 아닙니다.

문제 제기는 [권리 침해 대응](infringement-response.md)을 따릅니다. 운영상 판단과 법적 침해 확정은 구분합니다.

참고: [GitHub 라이선스 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)
